🛡 Defense-in-Depth Guardrail Architecture

🛡

Server-Side Lakera Policy Engine

LiteLLM binds lakera-input (pre_call) and lakera-output (post_call) via policy_attachments. Clients cannot disable or drop guardrails. Even on 429 fallback to openrouter/free, the exact guardrail policy is preserved.

🔒

nginx Strict Route Allowlist

Lakera v2 guards Chat Completions only. The nginx TLS sidecar forwards only /v1/chat/completions, /v1/models, /health/*, and /key/*. Requests to /v1/responses, /v1/messages, embeddings, or /ui get HTTP 403.

🔑

Scoped Virtual Key for n8n

make -C llmgw client-key CLIENT=n8n mints a least-privilege key stored hashed in Postgres: allowed on Lakera-blocking models only (no monitor/ or unguarded/), 30 RPM, 200k TPM, and zero admin rights.

📜

Strict TLS 1.2/1.3 & Private CAs

cert-manager mints private ECDSA P-256 CAs. llmgw enforces AES-256-GCM / ChaCha20-Poly1305 with HSTS. n8n verifies certs via NODE_EXTRA_CA_CERTS (ConfigMap llmgw-ca) — never disabling SSL verification.

🧱

Zero Public Exposure & NetPol

ClusterIP Services only — no Ingress, NodePort, or LoadBalancer. NetworkPolicy admits only namespace n8n to llmgw:8443, restricts egress to CoreDNS + Public :443, and blocks RFC1918 & cloud IMDS.

🧪

Hardened Pods & Zero Prompt Logs

All containers run non-root with all Linux capabilities dropped, seccomp RuntimeDefault, and automountServiceAccountToken: false. LiteLLM sets turn_off_message_logging: true and disables telemetry.
